# 安全复核

这次复核的是兼容门本身。它不是第三方脚本的安全认证，也不是 Android `isolatedProcess` 已经落地的证明。

## 执行边界

未信脚本只进入 Linux `gate-runner`。该进程：

- 只链接 QuickJS core，不编译 `quickjs-libc`，不提供 `std`、`os`、`require`、`process` 或 Java。
- 由 bubblewrap `--unshare-all --new-session --cap-drop ALL --clearenv` 启动。只读挂载运行器、preload 和系统库，不挂载仓库或家目录。
- seccomp 是允许列表。`openat`、`socket`、`execve` 在安装过滤器后必须返回 `EPERM`，否则进程直接退出，父进程等不到 isolation 记录。
- `RLIMIT_AS` 192MiB，`RLIMIT_CPU` 8 秒，`RLIMIT_NOFILE` 16，`RLIMIT_FSIZE` 0，`RLIMIT_CORE` 0。QuickJS 堆 32MiB，栈 2MiB。2MiB 是为了让官方 preload 自己的冻结遍历能完成，仍然是固定上限。
- 子进程在 `poll` 里检查会话墙钟，执行片内由 QuickJS interrupt 检查 CPU 时间。父进程另有线程，在会话预算或等待应答超时时 `destroyForcibly`。
- 独立进程本身不算权限沙箱。上面的命名空间、seccomp、rlimit 和父子看门狗才是边界。测试没有为了通过而放宽它们。

允许列表只在这套测试和当前 glibc 上验证过。它不是对全部系统调用的形式化审计。

## 网络

脚本进程没有 socket。HTTP 只发生在父进程：

- 只接受 `https`、443、没有 userinfo 和 fragment。
- 主机名只允许字母、数字和连字符，并且至少有一个点。`localhost`、`.local`、`.internal` 拒绝。
- 地址分类只解析数字字面量，不在分类函数里做 DNS。IPv4 拒绝前导零。IPv4 映射文本和 6to4 不放行。
- 连接使用已经判定为公网的 IP。SNI 和证书主机名校验仍用原来的名字。
- 每次重定向都重新准入和解析。测试覆盖了指向 `192.168.1.9` 的重定向，以及同时返回公网和 `127.0.0.1` 的应答；后一种情况一次连接都不做。
- gzip 解压有字节上限。超过上限的膨胀在测试里失败。
- 请求头拒绝换行和 `host`、`content-length`、`transfer-encoding`、`connection`、代理相关字段。脚本自己的 `authorization` 可以转发到它点名的公网主机，但测试和日志不记录头值。
- 唯一的真实请求是 `https://example.com/`。返回 200，正文含 Example Domain，对端地址通过公网判断。没有账号，没有音源接口。

## 没有做的事

- 没有把脚本放进 Node 或裸 JVM 的 `eval`。
- 没有把 Java 反射、文件或进程接口暴露给脚本。
- 没有执行已知的关机脚本，也没有执行 Huibq 或 QingLiang。
- 没有把样本、密钥或 keystore 写进仓库、日志或报告。
- Android 库不打开文件路径，只对传入的短字符串做带内存和时间上限的求值。它还没有放进 `isolatedProcess`，Linux 的 bubblewrap 也不能写成 Android 的权限承诺。

## 仍开放的缺口

- seccomp 允许 `fcntl` 和已有 fd 上的读写。脚本没有 FFI，但不能把这一点写成「原生内存漏洞也被挡住」。
- 二进制响应的脚本可见类型和旧 Buffer 不同。
- `formData` 未实现，调用会失败。
- 父进程传输没有做成 Android 上的独立 UID 服务。
- 依赖闭包只读了 AAR 清单。`kotlinx-coroutines-debug` 被图遍历带进来，并牵出 JNA；那不是播放器必需依赖。BOM 和 Kotlin POM 属性没有完全展开。最大已读 `minSdk` 是 21，但不能据此开始使用 Compose。
