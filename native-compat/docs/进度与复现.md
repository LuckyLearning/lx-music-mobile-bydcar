## 已核对的行为

测试直接跑仓库里的 preload（SHA-256 `e0e892ea9472e190aef6f16996ebcd6bec077f7d8659ceb87a30830d8a53fe41`，21341 字节），不是只检查它能解析。

- `lx.version` 是 `2.0.0`，`lx.env` 是 `mobile`。
- `kw/kg/tx/wy/mg/local` 的 actions 和音质按 preload 白名单取交集。`xm` 不在 `allSources` 循环里，`type != music` 的 `tx` 被跳过。
- `on()` 的 then、`inited`、请求处理函数、Promise 微任务的顺序与 preload 一致。
- 歌词：正文 51200 上限由 preload 抛错；`tlyric`/`rlyric` 长度必须 `< 5120`；`lxlyric` 必须 `< 8192`。
- `clearTimeout` 只删 JS 回调。宿主定时器仍会到，到了以后找不到回调就返回。
- 第二次调用 `lx.request` 返回的取消函数会碰到 `null` 并抛错。这是 preload 的可见行为，测试锁住它，没有改 preload。
- 宿主侧取消会让传输不再发出，并只回调一次 `request canceled`。旧版 `canceleFn` 空实现没有照抄。
- `formData` 明确失败，不会打开网络。`request.js` 里遍历 `options.form` 的分支因此没有被当成已支持。
- POST form 使用与 `encodeURIComponent` 相同的百分号编码。缺少精确键名 `Content-Type` 时，小写 `content-type` 仍会走 JSON 分支。
- 明文 `http://` 的 `musicUrl` 字符串仍被 preload 接受；播放准入和传输层拒绝明文。这是记下来的分叉，不是悄悄改脚本。
- 二进制响应在脚本里是 `{type:'Buffer', data:[0..255]}`，可以再组成 `Uint8Array`。它不是带 Node 方法的 Buffer 实例。
- `bufToString` 的 4 字节 UTF-8 仍得到 `U+07D9 U+2000`。BMP 的「中」仍然正确。测试没有改这个缺陷。
