# 音源对照

原版逻辑照搬。这里只记录模块对应关系和已经发现的差异。差异不是新的播放方案。

## 播放地址

原版 `src/core/music/utils.ts` 的 `handleGetOnlineMusicUrl` 调用 `musicSdk[source].getMusicUrl(musicInfo, quality)`。各平台 `src/utils/musicSdk/*/index.js` 再把 `getMusicUrl` 交给当前音源脚本。脚本请求的形状在 `src/core/init/userApi/index.ts`：`action` 是 `musicUrl`，`info.type` 是音质，`info.musicInfo` 是歌曲对象。失败后才按原版换源，不是客户端另找一个接口。

原生播放按钮现在用 `LegacyMusicUrl` 组出同样的请求，交给隔离进程里的脚本。脚本没有返回地址时，播放停在这里。

`KgPlay` 调用的 `m.kugou.com` `playInfo` 不是这条原版路径，不能当成 `getMusicUrl` 已经迁移。它只说明这个公开接口对 320k 哈希仍返回 128kbps 的同一文件。`trackercdn.kugou.com` 返回 20028「需要验证」，这是外部限制，没有绕过。

## 模块

| 原版 | 原生 | 状态 |
| --- | --- | --- |
| `src/core/init/userApi` 与 preload | 隔离进程里的官方 preload | 契约测试在跑。脚本正文不改。 |
| `musicSdk/kg/musicSearch.js` | `KgCatalog` | 搜索字段有夹具。不是 `getMusicUrl`。 |
| `musicSdk/kw/musicSearch.js` | `KwCatalog`、`KwSearch` | 解析有夹具。搜索地址是明文，没有实拉。 |
| `musicSdk/tx/musicSearch.js` | `TxCatalog.parseSongs` | 只迁了结果解析。签名请求没有迁。 |
| `musicSdk/wy/musicSearch.js` | `WyCatalog.parseResources` | 只迁了结果解析。eapi 没有迁。 |
| `musicSdk/mg/musicSearch.js` | `MgCatalog.parseResultList` | 只迁了结果解析。签名请求没有迁。 |
| `musicSdk/*/songList.js` | 未迁 | 酷我歌单地址是明文，没有为了测试去拉。 |
| `musicSdk/kg/index.js` `getMusicUrl` | 仍走脚本 | 不改成别的取链接口。 |
| 本机队列和歌单 | `LocalPlaylists` | 测试包自己的数据。不读旧版数据。 |
